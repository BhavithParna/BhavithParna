# Setup

This repo is the GitHub **profile README** repo. It only works if the repo is named
exactly `BhavithParna` (same as the username) and is **public**. Only `README.md` and
`assets/` are shown on the profile; this file is not.

## 1. Create and push

```bash
gh repo create BhavithParna --public --source=. --remote=origin --push
```

## 2. Let the snake see your private work

The contribution snake is generated by `.github/workflows/snake.yml` and pushed to the
`output` branch. With the default action token it only counts **public** contributions —
which badly understates you, since most of your commits are in private repos.

1. Create a classic PAT with the `repo` scope: <https://github.com/settings/tokens>
2. Add it as a repo secret named `GH_PAT`:
   ```bash
   gh secret set GH_PAT --repo BhavithParna/BhavithParna
   ```
3. Run it once: **Actions → generate snake → Run workflow** (or `gh workflow run snake.yml`).

Also switch on **Contribution settings → Private contributions** on your profile, so the
calendar itself reflects the private work.

## 3. Profile fields GitHub shows next to this README

These live in profile settings, not in this repo — <https://github.com/settings/profile>:

- **Bio** — currently empty. Something like: `Biomedical engineering @ BVRIT '27. Neural interfaces, mixed reality, medical instrumentation.`
- **Location** — `Hyderabad, India`
- **Website** — your portfolio URL once it's deployed
- **Avatar** — the current one is low-resolution and motion-blurred; a sharp 460×460+ image makes a disproportionate difference
- **Pinned repos** — Customize your pins → pick `NIMS-APP`, `VSAS`, `Portfolio` (private repos can be pinned too; they stay hidden from visitors)

## 4. Optional: accurate stat cards

`github-readme-stats.vercel.app` is currently **paused** (HTTP 503), which is why stat cards
are broken on profiles across GitHub right now. If you want them back *and* counting private
commits, deploy your own instance:

```bash
gh repo fork anuraghazra/github-readme-stats --clone
# deploy to Vercel, set PAT=<your classic token> in the project's env vars
```

Then add to `README.md`, pointing at your own deployment:

```html
<img src="https://<your-instance>.vercel.app/api?username=BhavithParna&count_private=true&include_all_commits=true&show_icons=true&theme=github_dark&hide_border=true&bg_color=0D1117&icon_color=3FB950&title_color=3FB950">
```

## Editing the README

The three animated SVGs are generated, not hand-edited:

```bash
python3 tools/gen_assets.py     # rewrites assets/boot.svg, divider.svg, ae86.svg
```

- `boot.svg` — the terminal: falling code rain, boot lines that type in, the name with a
  phosphor glow and a chromatic ghost, a sweeping scan bar and a tracking tear. Edit the
  `lines = [...]` list in `tools/gen_assets.py` to change what boots.
- `ae86.svg` — ASCII car, speed lines, moving road. The art is the `CAR` list in the generator.
- `divider.svg` — the running dashes between sections.

Notes for future edits:

- Animation is **SMIL only** (`<animate>`, `<animateTransform>`), no CSS and no `<script>`,
  which is what keeps it animating through GitHub's image proxy.
- Don't add a radial-gradient vignette over the screen. It was tried; Chrome renders it far
  darker than its stops suggest and it crushes the phosphor text to near-black. The scanline
  pattern alone carries the CRT look.
- Prose inside `<td>` cells must stay on **one line per paragraph** — GitHub turns source line
  breaks inside HTML table cells into `<br>` and the text breaks mid-sentence.
- Headless Chrome screenshots freeze SMIL at roughly t=0, so to check a later keyframe, strip
  the `<animate>` tags and force `opacity="1"` first.
